# CI 检查

第 3 层：每个 repo 的 `.github/workflows/ci.yml` 要跑的检查。每项检查拿代码和一份"标准答案"比对，标准答案由第 2 层的 CODEOWNERS 锁住（见 [repo-settings](../repo-settings/README.md) 的 CODEOWNERS 一行），改它要 owner 批准。CI 只比对，不重新生成标准答案。

检查按查什么分四组，另有一组按项目需要。"频率"一列：每个 PR，或定期。

## 结构

静态检查：代码对照锁住的规则，不运行代码。

| # | 检查 | 要求 | 标准答案（锁住的文件） | 防什么 | 频率 |
|---|---|---|---|---|---|
| 1 | 接口快照 | 用公开 API 工具从构建产物生成完整签名（参数类型、返回类型、默认值），和快照逐项比对：多、少、签名变了都失败。不靠数个数 | 接口快照 | 偷偷增删或改对外接口 | 每个 PR |
| 2 | 分层规则 | 只经接口使用下层，不越层，没有循环依赖 | 架构规则配置 | 越层调用、绕开接口 | 每个 PR |
| 3 | 分层覆盖全部模块 | 每个源码模块在架构规则里恰好归一层；没归层的失败 | 架构规则配置 | 新模块不归层，分层规则管不到 | 每个 PR |
| 4 | 实现名不越过工厂 | 具体实现的名字只出现在它自己的包、工厂和它自己的测试里；工厂之上不对接口对象做向下转型或按类型分支 | 架构规则配置 | 上层直接用具体实现，绕开接口 | 每个 PR |
| 5 | 副作用只在适配层 | 时钟、随机数、文件系统、网络、子进程、硬件 API 只在指定的适配模块里用 | 架构规则配置 | 副作用散在业务代码里，测试替换不了，结果随环境变 | 每个 PR |
| 6 | 测试边界 | 测试只 import 本单元的出口、下层接口和测试支持代码；只 mock 下层接口，不 mock 被测单元，也不 mock CI 工具 | 架构规则配置 | mock 掉被测代码或 CI 工具，测试测不到真东西 | 每个 PR |
| 7 | 不检测测试环境 | 发布代码不读 CI 或测试标记（CI 环境变量、测试框架是否已加载、测试模块以外的测试专用编译开关），不按主机名、用户、当前目录分支，不 import mock 库 | lint 配置、架构规则配置 | 在测试环境走特判，生产走另一条路 | 每个 PR |
| 8 | 逃生口白名单 | 动态 import、eval、反射访问私有符号、unsafe 或 FFI、不检查的强制转换成 any 类类型：每处都要在白名单里（路径、符号、原因） | 逃生口白名单 | 用逃生口绕开类型检查和分层规则 | 每个 PR |
| 9 | 不新增占位 | 发布代码里不新增 TODO、FIXME 或"未实现"占位（和 base 比 diff） | lint 配置 | 留占位冒充完成 | 每个 PR |
| 10 | lint 和格式 | 按配置跑，必须包含的规则见[通用规则](#通用规则) | lint 配置、formatter 配置、lint 基线 | 放宽规则 | 每个 PR |
| 11 | 类型检查 | 同 lint | 类型检查配置 | 放宽规则 | 每个 PR |
| 12 | 测试质量规则 | lint 配置必须开着：每个测试有断言；没有恒真或常量断言；没有 focus 或禁用的测试；测试里没有宽泛的 catch；测试里没有行内覆盖重试次数、超时、随机种子、样例数 | lint 配置 | 空测试、只跑部分测试、吞掉失败、在测试里局部放宽 | 每个 PR |
| 13 | 死代码 | 没有用不到的代码 | 检查配置 | 代码质量，不防作弊：工具把测试里的调用也算作使用 | 每个 PR |
| 14 | 重复代码 | 没有大段重复 | 检查配置 | 代码质量，不防作弊：改个名字就躲过 | 每个 PR |

## 测试执行

| # | 检查 | 要求 | 标准答案（锁住的文件） | 防什么 | 频率 |
|---|---|---|---|---|---|
| 15 | 测试结果状态门 | 结果文件存在，且是这次运行生成的；里面每个测试都是 passed：skipped、expected-fail、重试过、flaky 的数量为 0，状态白名单里的除外。另跑一次只收集不执行（collect-only），测试数要一致。测试 ID 和 merge-base 比，删掉或改名的 ID 让检查失败，删除名单里的除外 | 状态白名单、删除名单 | 加跳过标记、标成预期失败、重试到通过、改构建配置让测试不跑、删测试或改名、拿旧结果文件冒充 | 每个 PR |
| 16 | 契约测试矩阵 | 静态找出每个接口的全部实现（含 fake 和测试替身），每个都要出现在契约测试的结果里；接口快照里的每个接口都有一套契约测试；只跑契约测试，就要执行到每个接口方法 | 契约测试目录、接口快照 | 新实现不跑契约、接口没有契约、契约漏测方法、改弱契约 | 每个 PR |
| 17 | 总覆盖率 | 不低于门槛，也不低于 merge-base | 覆盖率门槛 | 少写测试、删测试 | 每个 PR |
| 18 | 改动行覆盖 | PR 改动的行被测试执行到的比例不低于门槛。门槛不设 100%：100% 会逼出空测试，断言由变异测试把关 | 覆盖率门槛 | 新代码不测，靠旧代码撑总覆盖率 | 每个 PR |
| 19 | 改动行变异测试 | 只变异 PR 改动的行；有变异体存活就失败，变异白名单里的除外 | 变异白名单 | 测试执行了代码，但不检查结果 | 每个 PR |
| 20 | 先失败后通过 | PR 新增或改过的测试拿去跑 base 的源码：PR 改了行为时，至少一个失败；在 head 上全部通过 | `.github/` 里的 CI 文件 | 测试没测到这次改的行为 | 每个 PR |
| 21 | 隔离再跑 | 契约测试（时间允许就全部测试）再跑一遍：去掉 CI 环境变量、断网、随机时区、locale 和时钟、换一个 checkout 路径、打乱顺序；每个测试有超时 | `.github/` 里的 CI 文件 | 第 7 项没抓到的测试环境特判；测试依赖顺序、网络或机器；测试卡住 | 每个 PR |

覆盖率只说明代码被执行过，不说明测试检查了结果：空测试也能把覆盖率刷上去。识破空测试要靠变异测试（工具在临时副本里把代码改坏，测试没失败就说明没检查结果；第 19、30 项），或者[顶层 README](../README.md) 第 5 层的隐藏验收测试。

## CI 完整性

核对其他检查真的跑了，而且没被动手脚。

| # | 检查 | 要求 | 标准答案（锁住的文件） | 防什么 | 频率 |
|---|---|---|---|---|---|
| 22 | 任务全跑 | 按改动只跑一部分任务时，最后核对该跑的任务都跑了、都成功 | `.github/` 里的范围规则 | 该跑的任务被判成不用跑 | 每个 PR |
| 23 | 工具版本 | 检查工具按它们自己锁定的清单安装，版本写死，和 PR 的依赖分开。跑检查工具的 job 不安装也不运行 PR 代码；运行 PR 代码的 job 只产出结果文件，由另一个 job 解析判定 | 检查工具清单 | PR 的代码或依赖改掉检查工具或它的结果；工具升级让检查悄悄变松 | 每个 PR |
| 24 | 行内豁免 | 各工具的豁免都算：lint、类型检查、覆盖率排除、跳过标记、死代码和重复代码的忽略、sanitizer 抑制、"生成文件"头。按工具分别数 base 和 head，数量上升就失败；正当的豁免放进白名单，每条写原因 | 豁免白名单 | 在代码里局部关掉检查 | 每个 PR |
| 25 | 配置只在锁住的路径 | 工具配置和测试运行器的钩子文件只能放在允许的路径 | 配置路径名单 | 嵌套的配置覆盖锁住的根配置；测试钩子把失败改成通过 | 每个 PR |
| 26 | 依赖门 | lockfile 和 base 比 diff：新增或变了的包必须在依赖白名单里；不准 path、git、URL 依赖，不准 override 或 patch，不准 submodule，不准新的 vendor 目录；安装脚本关掉；测试插件自动加载关掉；做漏洞和许可证扫描 | 依赖白名单 | 引入改过的包、在安装或测试时改结果的插件、有漏洞或许可证不合的包 | 每个 PR |
| 27 | 生成内容 | 生成文件用锁住的生成器重新生成，逐字节相同；带"生成"头的文件必须在生成路径名单里；二进制、压缩过的代码、大段编码数据、符号链接只能出现在二进制白名单里；golden 和快照文件锁住，测试从不以更新模式运行 | 生成路径名单、生成器配置、二进制白名单、golden 和快照目录 | 把逻辑藏进"生成"文件、二进制或编码数据躲过检查；改 golden 文件迁就错误输出 | 每个 PR |
| 28 | 只读范围 | 测试运行时，源码、测试、fixture、快照目录只读 | `.github/` 里的 CI 文件 | 测试运行中改源码、测试或快照 | 每个 PR |
| 29 | 工作区不变 | 全部跑完后 `git status --porcelain --ignored` 没有输出：构建产物、缓存、结果文件都写到工作区外 | `.github/` 里的 CI 文件、`.gitignore` | 测试或生成器偷偷改文件、改快照；写进被 ignore 的路径躲过检查 | 每个 PR |

## 定期

| # | 检查 | 要求 | 标准答案（锁住的文件） | 防什么 | 频率 |
|---|---|---|---|---|---|
| 30 | 全量变异测试 | 全部代码跑变异测试；存活的变异体补测试，或进变异白名单 | 变异白名单 | 测试执行了代码，但不检查结果 | 定期 |
| 31 | 重复跑测试 | 全套测试连跑 N 次（N 写在 CI 文件里）；任何一次失败的测试都算 flaky | 状态白名单 | 时好时坏的测试被重试或运气掩盖 | 定期 |
| 32 | 重型 sanitizer | 全部测试在内存、线程、未定义行为 sanitizer 下跑 | 豁免白名单 | 平时测试暴露不出的内存和并发错误 | 定期 |

定期结果必须强制，不能只当建议：比如失败自动开 issue，挡住下一次发布。

## 通用规则

每份锁住的配置至少包含这些规则。占位和测试质量的规则见第 9、12 项。

| 检查 | 规则 |
|---|---|
| 类型检查 | 最严格模式；不准隐式 any 或 unknown；公开函数的参数和返回值都写类型；可能为空的值先处理再用 |
| lint 正确性 | 没有用不到的变量和 import；不吞异常（空 catch、裸 except）；不遮蔽变量；浮点数不做相等比较；不用已废弃的 API |
| lint 可读性 | 函数长度、参数个数、嵌套深度、圈复杂度或认知复杂度、文件长度都有上限，现有超标的记进 lint 基线，基线只能变小；命名风格统一 |
| lint 危险写法 | eval、动态执行、unsafe 的规则开着，例外走第 8 项的逃生口白名单；库代码不用崩溃式捷径（unwrap、panic 之类）；测试里不 sleep、不读真实时间 |
| 格式 | formatter 用检查模式跑；CI 从不改写代码 |
| 注释预算 | 新增注释行数有上限：代码自己说明自己 |
